## 1. Git 命令手册

> 来源：[何君 · Git最全命令手册](https://zhuanlan.zhihu.com/p/654165242)（知乎）

### 1.1 Git 结构

![git 结构图示](https://img.thirra.com/blog/2026/11/23/a78e02775591-git-structure.jpg)

* `Workspace`：工作区
* `Index / Stage`：暂存区
* `Repository`：仓库区（本地仓库）
* `Remote`：远程仓库

**注：以下所有命令从** `$` **之后开始。**

### 1.2 新建代码库

| 说明 | 命令 |
| --- | --- |
| 在当前目录新建一个 Git 代码库 | `$ git init` |
| 新建一个目录，将其初始化为 Git 代码库 | `$ git init [project-name]` |
| 下载一个项目和它的整个代码历史 | `$ git clone [url]` |

### 1.3 配置

Git 配置信息在 `.git/config` 里面。

* `$ git --version`：查看 Git 版本号
* `$ which git`：显示当前 Git 路径
* `$ git config --list`：查看配置信息。可以看到 `user.name` 和 `user.email`。在当前项目下查看的配置是「全局配置 + 当前项目配置」，使用时会优先使用当前项目配置。

配置全局用户名和邮箱：

```bash
git config --global user.name "yourName"
git config --global user.email "yourEmail"
```

单独针对某一个项目配置用户名和邮箱：

```bash
git config user.name "yourName"
git config user.email "yourEmail"
```

### 1.4 增加、删除文件

| 说明 | 命令 |
| --- | --- |
| 添加指定文件到暂存区 | `$ git add [file1] [file2]` |
| 添加指定目录到暂存区，包括子目录 | `$ git add [dir]` |
| 添加当前目录的所有文件到暂存区 | `$ git add .` |
| 删除工作区文件，并且将这次删除放入暂存区 | `$ git rm [file1] [file2]` |
| 停止追踪指定文件，但该文件会保留在工作区 | `$ git rm --cached [file]` |
| 改名文件，并将这个改名放入暂存区 | `$ git mv [file-name] [file-renamed]` |

### 1.5 代码提交

| 说明 | 命令 |
| --- | --- |
| 提交暂存区到仓库区 | `$ git commit -m [message]` |
| 提交指定文件到仓库区 | `$ git commit [file1] [file2] ... -m [message]` |
| 提交工作区自上次提交之后的变化，直接到仓库区 | `$ git commit -a` |
| 提交时显示所有的 diff 信息 | `$ git commit -v` |
| 用一次新的提交替代上一次提交（无代码变化时可用于改写上次提交信息） | `$ git commit --amend -m [message]` |
| 重做上一次提交，并包括指定文件的新变化 | `$ git commit --amend [file1] [file2]` |

### 1.6 分支

| 说明 | 命令 |
| --- | --- |
| 列出所有本地分支 | `$ git branch` |
| 列出所有远程分支 | `$ git branch -r` |
| 列出所有本地分支和远程分支 | `$ git branch -a` |
| 新建一个分支，但依然停留在当前分支 | `$ git branch [branch-name]` |
| 新建一个分支，并切换到该分支 | `$ git checkout -b [branch-name]` |
| 切换到指定分支，并更新工作区 | `$ git checkout [branch-name]` |
| 将现有分支与指定远程分支建立追踪关系 | `$ git branch --track [branch] [remote-branch]` |
| 合并指定分支到当前分支 | `$ git merge [branch]` |
| 删除分支 | `$ git branch -d [branch-name]` |
| 删除远程分支 | `$ git push origin --delete [branch-name]` |

### 1.7 标签

| 说明 | 命令 |
| --- | --- |
| 列出所有 tag | `$ git tag` |
| 在当前 commit 新建一个 tag | `$ git tag [tag]` |
| 在指定 commit 新建一个 tag | `$ git tag [tag] [commit]` |
| 删除本地 tag | `$ git tag -d [tag]` |
| 删除远程 tag | `$ git push origin :refs/tags/[tagName]` |
| 查看 tag 信息 | `$ git show [tag]` |
| 推送指定 tag | `$ git push [remote] [tag]` |
| 推送所有 tag | `$ git push [remote] --tags` |

### 1.8 查看信息

| 说明 | 命令 |
| --- | --- |
| 显示变更的文件 | `$ git status` |
| 显示暂存区和工作区的差异 | `$ git diff` |
| 显示你今天写了多少行代码 | `$ git diff --shortstat "{0 day ago}"` |
| 显示当前分支的最近几次提交 | `$ git reflog` |

### 1.9 远程同步

| 说明 | 命令 |
| --- | --- |
| 将现有仓库与远程仓库建立联系 | `$ git remote add origin [remote address]` |
| 下载远程仓库的所有变动 | `$ git fetch [remote]` |
| 显示所有远程仓库 | `$ git remote -v` |
| 取回远程仓库的变化，并与本地分支合并 | `$ git pull [remote] [branch]` |
| 上传指定分支到远程仓库 | `$ git push [remote] [branch]` |
| 推送所有分支到远程仓库 | `$ git push [remote] --all` |

### 1.10 回退

| 说明 | 命令 |
| --- | --- |
| 恢复暂存区的指定文件到工作区 | `$ git checkout [file]` |
| 重置当前 HEAD 为指定 commit，同时重置暂存区和工作区 | `$ git reset --hard [commit]` |
| 恢复暂存区所有文件到工作区 | `$ git checkout .` |
| 远程版本回退 | 先本地回退，再执行：`$ git push origin HEAD --force` |

### 1.11 暂存

| 说明 | 命令 |
| --- | --- |
| 暂存 | `$ git stash` |
| 查看暂存记录 | `$ git stash list` |
| 恢复暂存并删除这个记录 | `$ git stash pop stash@{index}` |
| 恢复暂存并保留这个记录 | `$ git stash apply stash@{index}` |
| 删除某个暂存记录 | `$ git stash drop stash@{index}` |
| 删除全部暂存记录 | `$ git stash clear` |

### 1.12 其他

| 说明 | 命令 |
| --- | --- |
| 生成一个可供发布的压缩包 | `$ git archive` |
| 将一个或多个特定的提交应用到当前分支（非常有用） | `$ git cherry-pick` |

### 1.13 其它问题

`git pull` 时报错：

```text
error: cannot lock ref 'xxx': ref xxx is at （一个 commitID） but expected
```

处理方式：

1. 使用 git 命令删除相应 refs，例如：

   ```bash
git update-ref -d refs/remotes/origin/git/yousa/feature_01
```
2. 简单粗暴强行拉取：

   ```bash
git pull -p
```

## 2. Git 管理规范

> 来源：[青灯照颦微 · git管理规范--分支命名规范、CommitMessage规范](https://blog.csdn.net/sinat_32872729/article/details/146343243)（CSDN）

### 2.1 分支命名规范

2.1.1 主分支（main / master）

* **名称**：`main` 或 `master`
* **用途**：存放稳定的、可发布的代码
* **规则**：只有一个主分支；不允许直接在主分支上提交代码，只能通过合并其他分支来更新

2.1.2 开发分支（develop）

* **名称**：`develop`
* **用途**：集成开发中的功能分支
* **规则**：从 `main` 分支创建；功能开发完成后，合并到 `develop` 分支

2.1.3 功能分支（feat）

* **名称**：`feature/<feature-name>` 或 `feat/<feature-name>`
* **用途**：开发新功能
* **规则**：从 `develop` 分支创建；功能开发完成后，合并回 `develop` 分支
* **示例**：`feature/user-authentication`、`feat/add-payment-gateway`

2.1.4 修复分支（fix）

* **名称**：`bugfix/` 或 `fix/`
* **用途**：修复 bug
* **规则**：从 `develop` 分支创建；修复完成后，合并回 `develop` 分支
* **示例**：`bugfix/login-error`、`fix/null-pointer-exception`

2.1.5 发布分支（release）

* **名称**：`release/`
* **用途**：准备发布新版本
* **规则**：从 `develop` 分支创建；发布完成后，合并到 `main` 和 `develop` 分支
* **示例**：`release/v1.0.0`、`release/2023-10-01`

2.1.6 热修复分支（hotfix）

* **名称**：`hotfix/`
* **用途**：紧急修复生产环境中的 bug
* **规则**：从 `main` 分支创建；修复完成后，合并到 `main` 和 `develop` 分支
* **示例**：`hotfix/critical-security-issue`、`hotfix/login-page-crash`

2.1.7 支持分支（support）

* **名称**：`support/`
* **用途**：维护旧版本
* **规则**：从 `main` 分支创建
* **示例**：`support/v1.0.x`

### 2.2 分支命名最佳实践

* **使用小写字母和连字符**：避免空格或特殊字符

  + 正确：`feature/user-authentication`
  + 错误：`feature/User Authentication`
* **包含上下文信息**：在分支名中明确用途

  + 示例：`fix/api-rate-limit`
* **关联 Issue 或任务编号**

  + 示例：`feature/PROJ-123-add-search`
* **避免过长名称**：简洁且信息完整

  + 示例：`feat/add-payment-gateway`，而不是 `feat/add-payment-gateway-integration-with-stripe`

2.2.1 更多示例

| 场景 | 示例 |
| --- | --- |
| 功能开发 | `feature/user-profile`、`feat/add-search-functionality` |
| Bug 修复 | `bugfix/login-error`、`fix/api-timeout-issue` |
| 发布准备 | `release/v1.2.0`、`release/2023-10-01` |
| 热修复 | `hotfix/critical-security-issue`、`hotfix/payment-gateway-crash` |
| 支持旧版本 | `support/v1.0.x`、`support/legacy-api` |

### 2.3 Git Commit Message 规范

2.3.1 格式

```text
<type>(<scope>): <subject>

<body>

<footer>
```

2.3.2 type

推荐的 type 类型：

| type | 含义 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复 bug |
| `docs` | 仅文档更改 |
| `style` | 不影响代码含义的更改（空白、格式、缺失分号等） |
| `refactor` | 代码重构（既不修复 bug 也不新增功能） |
| `perf` | 改进性能的代码更改 |
| `test` | 添加缺少的测试或更正现有测试 |
| `chore` | 对构建过程或辅助工具和库的更改 |
| `ci` | 自动化流程配置修改 |
| `revert` | 回滚到上一个版本 |

2.3.3 Scope

Scope（范围，可选）：说明提交的影响范围。例如：

* `feat(login)`：登录功能的新增
* `fix(api)`：API 模块的修复

2.3.4 Subject

Subject（主题）：简洁描述提交目的，建议不超过 50 个字符。

2.3.5 Body

* 详细描述提交的内容和背景
* 说明为什么需要这次提交，以及如何实现
* 每行建议不超过 72 个字符

2.3.6 Footer

用于关联 Issue、Breaking Changes 等：

* 关联 Issue：`Closes #123` 或 `Fixes #123`
* Breaking Changes：`BREAKING CHANGE: <描述>`

2.3.7 示例

**示例 1：新增功能**

```text
feat(login): add OAuth2 support

- Implement OAuth2 login flow
- Add support for Google and GitHub providers
- Update user authentication logic

Closes #45
```

**示例 2：修复 bug**

```text
fix(api): resolve null pointer exception

- Add null check for user input
- Update error handling logic

Fixes #123
```

**示例 3：文档更新**

```text
docs(readme): update installation instructions

- Add steps for setting up OAuth2
- Fix broken links
```

**示例 4：代码重构**

```text
refactor(auth): simplify token validation logic

- Remove redundant checks
- Extract token validation into a separate function
```

**示例 5：性能优化**

```text
perf(database): optimize query performance

- Add indexes to frequently queried columns
- Cache query results for 5 minutes
```
